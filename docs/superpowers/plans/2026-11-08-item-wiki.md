# Item Wiki Implementation Plan

**Goal:** Add Wiki → Vật Phẩm to the existing local admin with all item definitions, searchable ID, real game icon, name and function.

**Architecture:** Read TSV definitions recursively from gameserver/setting/item, accepting template tables with Name/Icon/Genre/DetailType/ParticularType/Level. Preserve repeated IDs with their source, including supplemental definitions. Search the complete catalog on the server and return a bounded page. Convert referenced client SPR assets into static PNGs with a reproducible standard-library Python script.

**Tech Stack:** Existing Next.js 16 / React 19 / TypeScript; Python standard library for legacy assets. Local Windows application only.

**Implementation choices:** Match existing admin theme. ID is Genre,DetailType,ParticularType,Level (not ObjID). Intro/Help supply function text; missing descriptions receive a clearly generic category description. No execution of item scripts. Keep all template records and show source in expandable details. Search ignores Vietnamese accents and accepts comma/space ID notation. 50 records per page, category filter, total counts and manual refresh.

- [x] Catalog: test TSV handling, numeric IDs, duplicate preservation, Vietnamese search, complete-file counting, pagination and errors; implement lib/item-wiki.ts and shared types.
- [x] Icons: test SPR palette/RLE including transparency and truncation; implement scripts/export-item-icons.py using PACK filename hash and NRV2B; export all available icons and a coverage manifest.
- [x] UI/API: add read-only local API, loading/error/empty states and responsive list; add Wiki navigation and README.
- [x] Verify: full npm test, typecheck, production build, real HTTP queries including final page and icon coverage; inspect desktop and narrow layouts when browser automation is available.

**Review focus:** Duplicate IDs; empty/non-item tables; embedded markup; accented names and exact IDs; missing/corrupt images; out-of-range pagination; updates to source files; stale fetch results.

**Ledger:** Existing workspace has no Git repository. Reuse this local checkout, preserve server/client data, and do not start or stop game processes. Ruling: require the Icon column to identify item template tables; five reward/conversion tables also have GDPL columns but only reference items. Actual template rows with empty icons are retained. Source origins distinguish supplemental/duplicate definitions.

**Verification:** 20,516 template rows / 18,691 distinct IDs / 50 files; 20,329 rows have icons. Exported 2,016 of 2,033 distinct referenced icon paths; 17 paths absent from Client. Four catalog tests plus three sprite tests pass. Full npm test: 50 pass / 3 MySQL integration tests intentionally skipped; typecheck and production build pass. The initial sandbox test run could not create junctions and build could not mkdir .next; both succeeded outside the sandbox. HTTP checks verify all counts, final page 411 (16 rows), exact ID search, image PNG signature, no-result handling, 200-row cap and cross-site rejection. Browser verifies unaccented search, exact ID, empty/reset, desktop and 390px layouts, and same-page jump regression (reproduced before guard, passes after). Independent code review found no remaining actionable issues after the guard and table classification fixes.
