# Accounts Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task.

**Goal:** Add Tài khoản to the existing admin menu, with simple game-account registration above the account list.

**Architecture:** Reuse AdminShell and the existing cream/green styles. A local-only Node API reads the existing Paysys database configuration and uses parameterized MySQL queries against jxaccount.account. Keep the game's existing password format and database schema.

**Tech Stack:** Next.js 16, React, TypeScript, mysql2, node:test.

**Spec:** User request: registration above, account list below, keep registration simple. Implementation choices: username, password and confirmation only; display latest 200 accounts and total; reject duplicate names; show loading, empty, success and error states.

## Global Constraints

- Existing localhost request guard applies to both API methods.
- Never return passwords, hashes or database configuration to the browser.
- Do not alter database schema or existing accounts.
- No Git repository is present; changes stay in the current workspace.

## Review Focus

- Invalid/null payloads must fail before database access.
- Duplicate names differing by case must not create another account.
- Concurrent submissions must serialize duplicate checking and insertion.
- Database failures must display useful messages without SQL or credentials.
- Registration success must remain clear even if the subsequent list refresh fails.
